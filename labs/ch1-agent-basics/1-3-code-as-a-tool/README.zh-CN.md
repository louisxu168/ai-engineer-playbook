# 实验 1-3：让 agent 写代码来「想」

[English](README.md) · **简体中文**

> **你会学到什么**
>
> 1. Deep Research 循环长什么样：`搜索 → 读正文 → 写代码分析 → 再搜索`
> 2. 给 agent 代码工具，**真正的理由不是「它算不对」** —— 现代模型心算强得超乎你想象
> 3. 真正的理由是**可验证性**：代码能被第三方复制去重跑，一段散文推导不能
>
> **怎么学**：先猜 → 再跑 → 对照。这个实验有个特点 ——
> **你的预测很可能会错，而且是「它比你想的更强」那种错。** 那正是重点。
>
> **需要多久**：核心 15 分钟，全做完约 45 分钟。
>

## 第 0 步：跑通完整的深度研究循环（8 分钟）

### 🔧 做什么

```bash
cd labs/ch1-agent-basics/1-3-code-as-a-tool
python3 agent.py deep
```

它会问你想研究什么。直接回车看例子，输编号即可选，比如输 `1`：

```
世界最高的 5 座建筑，平均高度是多少米？最高的那座比平均值高出百分之多少？
```

**不用 `pip install`，不用 API key。**

### 👀 观察什么

这个实验比前两个多了一件事：**它会写代码**。留意这样的输出：

```
  [工具] run_python
  ┌─ 它写的代码 ─────────────────────────
  │ h = {'Burj Khalifa': 829.8, 'Merdeka 118': 678.9, ...}
  │ avg = sum(h.values())/len(h)
  │ print('average =', round(avg,2))
  │ print('pct above avg =', round((max(h.values())-avg)/avg*100,2))
  └──────────────────────────────────────
        -> {'stdout': 'average = 668.16\npct above avg = 24.19'}
```

同时留意整个循环的形状：**它并不是一口气查完再算**，而是查一点、发现不够、
再查、再算。这就是 Deep Research 循环。

## 第 1 步：先猜，再拿掉代码工具（10 分钟）

### 🤔 先猜（这题很多人会猜错）

我们要拿掉 `run_python`，让它只能心算。猜一下：

- 它还能算对吗？ ___
- 你觉得错的概率有多大？ ___

### 🔧 做什么

```bash
python3 agent.py no_code "（复制第 0 步用的同一个问题）"
```

### 👀 观察什么

**把两个数字并排放着看。**

### 💡 学到什么

如果你猜「它会算错」—— 你和我一样猜错了。**实测中它算对了**，
一位小数都不差。

我还单独做了个更狠的测试：直接扔给它 20 个三位小数，要求纯心算求
中位数和总体标准差。它给出 `518.65, 93.94`，真值 `518.65, 93.9437`。**全对。**

> **所以「模型算不对」不是给它代码工具的理由。**
> 这个实验最初就是照那个假设设计的，被实测推翻了，我把它改了。

那真正的理由是什么？三条：

| 理由 | 说的是什么 |
|---|---|
| **你验不了** | 散文推导只能自己重算一遍；代码可以复制去跑 |
| **改假设很贵** | 有代码改一个数重跑；没代码整套重来 |
| **规模一大就崩** | 20 个数能心算，2 万行日志不能 |

第二条在实测中**自己冒出来了**：哈利法塔算 829.8（含天线）还是 828（屋顶）？
**有代码的那次主动把两种都算了，没代码的那次没有。** 详见 SOLUTION。

## ⚠️ 安全提醒：`run_python` 不是沙箱

这个实验会**执行模型生成的 Python 代码**。我们只加了一个超时限制 ——
那远远不算沙箱，这段代码仍然能读写你的文件。

本实验里模型写的都是「对已取回的数字做算术」，风险很低。但：

> **真实项目绝对不能这样跑模型生成的代码。**
> 必须放进容器（Docker / gVisor / Firecracker 之类），切断网络和文件系统。

原书那个实验用的是 OpenAI 托管的 `code_interpreter` —— 沙箱在厂商那边。
我们没有厂商托管的沙箱，所以这里是个教学用的简化版，代码里也写明了这一点。

## 附：概念速查

### Deep Research 循环

```
搜索 → 读正文 → 写代码分析 → 发现还缺数据 → 再搜索 → …
```

和实验 1-1 的 ReAct 循环**是同一个循环**，只是工具多了一件（`run_python`）。
到这里你应该能确认一件事：**前三个实验用的是同一套机制，变的只有工具。**

### 三个工具的分工

| 工具 | 干什么 | 属于哪个阶段 |
|---|---|---|
| `search(query)` | 找线索 | 取数据 |
| `read(title)` | 拿具体数字 | 取数据 |
| `run_python(code)` | 算、比、排序、统计 | **分析** |

前两个是「取回」，第三个是「分析」。**这个实验讲的就是第三件事。**

### 三个实验串起来看

| 实验 | 问的问题 | 结论 |
|---|---|---|
| 1-1 | 上下文是什么？ | 就是一段你拼出来的字符串 |
| 1-2 | 工具由谁跑？ | 选 hosted，放弃的是可观测性 |
| 1-3 | 分析靠什么算？ | 选代码，得到的是可复现性 |

**1-2 和 1-3 其实是同一件事的两面：你想要的是「能被检查的过程」。**

## 卡住了？

| 你看到的 | 怎么办 |
|---|---|
| `✗ 没找到可用的后端` | 按屏幕上的三个选项装任意一个 |
| 跑满 16 轮没给答案 | 正常，深度研究本来就慢。换个数据更好找的问题再试 |
| `代码跑了超过 15 秒` | 模型写了个死循环或太重的计算，它通常会自己改写重试 |
| 忘了有哪些命令 | 敲 `python3 agent.py`（不带参数） |
