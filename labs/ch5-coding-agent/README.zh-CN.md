## 这一章想让你建立什么

**5-1** 问的是每个 coding agent 都绕不开的第一个问题：
**让模型用什么格式说「改哪儿」？**

它拿同一个 bug 测三种答案，得到的是**算术结论**而不是观点：
`whole_file` 的成本跟着**文件大小**走，`search_replace` 和 `line_range`
跟着**改动大小**走。改动量翻 8 倍，`whole_file` 只涨 1.07% ——
这就是为什么所有真实产品都拿 diff 类格式做日常默认，
只在大重写时才整份输出。

而更重要的是安全那一半。**`line_range` 是三种里唯一一个"出错时可能不报错"的**：
行号偏一行，那次编辑照样能"成功"应用，只是改到了别的地方。
所以**便宜 ≠ 该优先选** —— 最省的那个恰恰是最不该信的那个。

这个实验还带着本仓库**最硬的判据**：它真的跑 `unittest`。
前面所有实验检查的是「输出长什么样」，这个检查的是「代码干了什么」。

## 跑法

每个实验都是**独立文件夹**，自带全部代码：

```bash
cd 5-1-edit-formats
python3 agent.py            # 先看用法说明
```

不需要 API key。

⚠️ 这一章会**执行代码**。实验跑的是一份用完即弃的副本，也拦住了改判据的路，
但**它们不是沙箱** —— 真实项目请用容器。
