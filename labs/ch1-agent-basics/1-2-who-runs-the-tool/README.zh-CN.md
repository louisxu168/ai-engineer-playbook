# 实验 02：工具由谁来跑？

[English](README.md) · **简体中文**

**要搞明白的问题**：当 agent 用工具时，**真正执行工具的是你，还是厂商？**

---

## 一、两条路，都成立

实验 01 里，工具是你自己写的 Python 函数，循环也是你自己写的。模型只负责**说出**
它想调什么。

但现在的模型很多**自带工具**。你直接问 Claude Code 一个问题，它会自己联网搜索、
自己读网页、自己给答案 —— 你一行循环都没写。

这就是所谓**「模型即 Agent」**：harness 在厂商那边。

| | 谁跑循环 | 谁跑工具 | 你写多少代码 |
|---|---|---|---|
| **hosted** | 厂商 | 厂商 | 0 行 |
| **DIY** | 你 | 你 | 整个循环 |

两条路都是对的，代价不同。这个实验让你**亲手体会那个代价** —— 同一个问题，五种跑法。

---

## 二、五种模式

| 模式 | 做什么 |
|---|---|
| `hosted` | 把问题原样丢给 Claude Code，允许它用自带的 WebSearch。你什么都不用做 |
| `diy` | 你实现 `search` / `read` / `calc`，你跑循环。每一步都看得见 |
| `no_search` | 你跑循环，但**不给它搜索工具**（基线：只能靠记忆） |
| `diy_titles_only` | `search` 只返回标题，不返回摘要 |
| `diy_top1` | `search` 只返回 1 条结果，而不是 3 条 |

后两个是**工具降级**。它们只改 `search` 的**返回内容**，循环代码一个字没动 ——
用来证明一件事：**工具返回什么，比循环怎么写更重要。**

---

## 三、动手

```bash
pip install -r requirements.txt
python3 agent.py                # 看用法
python3 agent.py hosted         # 先跑这个
python3 agent.py diy            # 再跑这个，对比
```

`hosted` 模式需要 Claude Code（用它自带的 WebSearch）。
`diy` 系列用维基百科公开 API —— **不需要 key，只用 Python 标准库**。

### 第 1 步：跑 hosted，注意你「看不到」什么

```bash
python3 agent.py hosted
```

它会答得又快又好，带一堆来源链接。然后问自己：

> 它搜了什么关键词？打开了哪几个网页？读到过什么？中间失败重试过吗？

**一个都答不上来。** 你拿到的只有最后那段文字。程序结尾会把这句话打出来提醒你。

### 第 2 步：跑 diy，注意你能看到什么

```bash
python3 agent.py diy
```

慢很多。但每一次搜索、每一段摘要、每一次失败，全在你眼前。

实测跑出来的轨迹（节选）：

```
第 1 轮  [思考] 先分别搜索迪拜和上海的最高建筑…
        [工具] search({'query': '迪拜最高建筑 哈利法塔 高度'})
              -> {"error": "没搜到结果"}                      ← 失败了！

第 2 轮  [思考] 中文关键词搜不到，改用英文名称搜索。
        [工具] search({'query': 'Burj Khalifa'})
              -> {"results": [{"title": "Burj Khalifa", "snippet": "…megatall
                 skyscraper in Dubai…"}]}                     ← 自我纠正

第 3 轮  [思考] Shanghai Tower 摘要给出 632 米，但 Burj Khalifa 摘要没给数字，
                需要读正文拿到精确高度。
        [工具] read({'title': 'Burj Khalifa'})
              -> {"extract": "…total height of 829.8 m…"}     ← search 只给线索

第 4 轮  [工具] calc({'expression': '828 - 632'}) -> 196
```

**这四轮里藏着三个真实的教学点**，而 hosted 模式一个都不会让你看见：

1. **第 1 轮搜索失败了** —— 中文关键词打英文维基百科，零结果
2. **第 2 轮它自己纠正了** —— 换成英文名再搜。真实 agent 的容错就长这样
3. **第 3 轮暴露了 search 和 read 的分工** —— 上海中心的摘要恰好带了 632 米，
   哈利法塔的摘要**没有数字**，所以必须去读正文

第 3 点是这个实验最想让你注意的：

> **search 返回的是线索，不是答案。**

这正是「agentic search」和「朴素 RAG」的分界线。朴素 RAG 把检索结果一股脑塞进
prompt 就完事了；agentic search 会判断"这条线索够不够"，不够就再去读。

### 第 3 步：先预测，再跑降级模式

```bash
python3 agent.py diy_titles_only   # search 只给标题
python3 agent.py diy_top1          # search 只给 1 条
python3 agent.py no_search         # 完全不给搜索
```

跑之前先猜：**轮数会变多还是变少？还答得对吗？**

提示：这三个模式，`run_diy()` 循环里**一行代码都没改**。改的只有
`execute_tool()` 里 `search` 的返回内容。

### 第 4 步：对比表

```bash
python3 agent.py all      # 约 4~10 分钟
```

## 四、代码怎么读

`agent.py` 分五部分：

| 部分 | 内容 | 重点 |
|---|---|---|
| 1 | 工具：`search` / `read` / `calc` | 注意 search 和 read 是**两个**工具 |
| 2 | 系统提示词 | `no_search` 消融在这 |
| 3 | 上下文拼接 | 和实验 01 一样，这里不再消融上下文 |
| 4 | **两个 runner** ★ | `run_hosted()` vs `run_diy()` —— 对比本身就是本实验 |
| 5 | 命令行入口 | 可跳过 |

**直接对比第 4 部分的两个函数**：

- `run_hosted()` —— 十几行，**没有循环**。因为循环不在我们这边。
- `run_diy()` —— 完整的 ReAct 循环，和实验 01 是同一个。

第二点值得说破：**「会联网搜索的 agent」不需要任何新机制。** 还是那个循环，
只是工具换了。你在实验 01 学的东西，直接就能用。

`llm.py` 里也有同样的对照：

```python
complete()          # 禁止厂商自带工具 → 循环归你
complete_hosted()   # 打开 WebSearch   → 整件事归厂商
```

两个函数的差别只有一行：`--disallowedTools` 换成 `--allowedTools WebSearch`。

## 五、怎么选？

| | hosted | DIY |
|---|---|---|
| 开发成本 | 几乎为零 | 要写循环、写工具、调 prompt |
| 答案质量 | 通常更好（真·全网搜索） | 取决于你的工具 |
| **可观测性** | **几乎为零** | **全部可见** |
| 出错时能 debug 吗 | 很难 | 能定位到具体哪一步 |
| 能换搜索源吗 | 不能 | 能（换成公司内网、私有库…） |
| 能控制成本吗 | 有限 | 能（限制轮数、缓存、降级） |
| 数据出不出去 | 出去 | 你说了算 |

**没有标准答案。** 真实项目里常见的组合是：

- 通用问答、原型验证 → hosted，快
- 需要接私有数据、需要审计日志、需要控制成本 → DIY
- 很多产品是**混合**：主流程 DIY，某些子任务调用厂商托管工具

这个实验想让你建立的判断力是：**当你选 hosted 时，你放弃的是可观测性。**
出事那天，你手上只有最终那段文字。

## 六、练习

1. **换个模型记忆不可能知道的问题**，比如最近一周的新闻、某个冷门数据。
   再跑 `no_search`，看它怎么办。（见 SOLUTION 里那个意外）
2. **给 `read` 加个字数上限**（比如 `chars=100`），看它够不够用。
3. **让 `search` 返回过时数据** —— 比如硬编码一条错误的摘要，看它会不会照单全收。
4. **数一数**：`run_hosted()` 有几行？`run_diy()` 有几行？这个比例说明了什么？
5. **给 diy 模式加缓存** —— 同一个 query 第二次直接返回上次结果。想想真实项目
   里这能省多少钱。
