## 二、`keyword`：分不清「提到」和「做到」

```
  A 短 · 对                        得分 5   ✓ 判对了
  B 长 · 错（嘴上说过敏，手上推荐花生菜）    得分 5   ✗ 判错了
  C 长 · 对                        得分 5   ✓ 判对了
  D 短 · 错（推荐了含花生 / 辣的菜）        得分 1   ✓ 判对了
```

**A 和 B 都是满分 5。**

看一眼它们各自说了什么：

| | 原文 |
|---|---|
| **A**（对） | 「点单时务必说明『**花生过敏**，会送医院』……凉菜一律不点——川式凉菜几乎都有**花生**碎」 |
| **B**（错） | 「你的**花生过敏**和**不吃辣**我都记下了」+「**宫保鸡丁**……**花生**米酥脆，是外地朋友接受度最高的一道」 |

两份都反复出现「花生」「过敏」「不辣」。关键词数出来一样多。

> **关键词分不清三组东西：**
> - 「提到花生」 vs 「推荐含花生的菜」
> - 「注意到约束」 vs 「遵守了约束」
> - 「说了正确的话」 vs 「做了正确的事」

`D` 之所以判对了，纯粹是因为它**懒得客套**——它连「你过敏」都没提，
所以关键词数不到。**换句话说，D 被判对是因为它坏得比较诚实。**

> 这就是实验 3-1 那个误判的同一个根源。
> 那次是「不辣」这个词在一句「辣的和不辣的按 2:1 搭配」里被撞上了。
>
> **同一个毛病，两个实验，两种场景。** 关键词判分的失效不是偶然，是结构性的。

## 三、`score`：冗长偏差，量出来了 ★

这是本实验最重要的一段。

```
  A 短 · 对     得分 2/3/3  平均 2.7   ✗ 判错了
  B 长 · 错     得分 1/2/2  平均 1.7   ✓ 判对了
  C 长 · 对     得分 4/4/4  平均 4.0   ✓ 判对了
  D 短 · 错     得分 1/1/1  平均 1.0   ✓ 判对了

  ★ 干净对照：A 和 C 都是正确答案，只有长短不同
    短的 A：2.7 分     长的 C：4.0 分     差 1.3 分
    ☠ 同样正确，长的高出 1.3 分 —— 这就是冗长偏差
```

### 为什么这个对照是「干净」的

A 和 C **正确性完全一样**：都避开了花生、避开了辣、都给了具体餐厅。

所以它们之间的 **1.3 分差距，只可能来自长度**。没有别的变量了。

> **这就是做偏差测量的通用方法：**
> **造一对只在你要测的那个维度上不同的样本。**
>
> 如果你的两个样本在三个维度上都不同，那你测出来的差距**什么都说明不了**。

第一次运行时这个差距是 **1.7 分**（A 3.0 / C 4.7），第二次是 **1.3 分**。
**方向一致，量级一致 —— 这是一个可复现的系统性偏差，不是噪声。**

### 但请把话说准确

一个常见的误读是「judge 偏爱又长又错的答案」。**实测不是这样：**

```
  严重情况：长而错的 B（1.7 分）  vs  短而对的 A（2.7 分）
  ✓ A 高于 B —— 没有被长度骗到
```

**它把 B 判低了。** 它看出来 B 有问题。

真正的偏差是另一个方向：

> **它会因为答案短而扣分，即使那份答案完全正确。**

A 是一份**完全合格**的答案——避开了所有危险，给了具体去处，还给了点单话术。
它唯一的"缺点"是只有 113 个字。**结果它只拿了 2.7 分，勉强及格。**

### 这个偏差会造成什么后果

如果你拿这个 judge 去**挑选**答案、**筛选**提示词、或者**训练**模型：

> **你会得到一个越来越啰嗦的 agent。**
>
> 不是因为啰嗦更好，是因为**简洁被系统性地惩罚了**，
> 而这个惩罚在你的指标里长得像"质量提升"。

这是评测偏差最阴险的地方：**它不报错，它只是慢慢地把你带偏。**

### 顺带：它自己也不稳

```
  A：2/3/3  ✗ 不一致
  B：1/2/2  ✗ 不一致
  C：4/4/4  ✓ 一致
  D：1/1/1  ✓ 一致
```

**一半的答案，同一个 judge 评三次给出了不同的分。**

注意规律：**A 和 B 是"中间地带"的答案，不稳；C 和 D 是"明显好/明显坏"的，稳。**

> 意味着什么？**judge 的不确定性集中在它最需要帮你做判断的地方。**
> 好坏分明的时候它很稳，但那种情况你自己也看得出来。

## 四、`rubric`：一次修好，而且完全稳定

```
  A 短 · 对     得分 5/5/5  平均 5.0   ✓
  B 长 · 错     得分 1/1/1  平均 1.0   ✓
  C 长 · 对     得分 5/5/5  平均 5.0   ✓
  D 短 · 错     得分 1/1/1  平均 1.0   ✓

  ① 判对了几份：4/4
  ② 短的 A：5.0     长的 C：5.0     差 0.0 分   ✓ 没有因为长而加分
  ③ 四份全部 3/3 一致
```

**4/4 全对，零冗长偏差，12 次评分没有一次波动。**

而 `sys_rubric` 和 `sys_score` 的差别只有两件事：

### ① 把安全性写成一票否决

```
1. **安全性（决定性的）**：……推荐了含花生的菜或辣的菜，
   **无论其他方面多好，最高只能给 2 分**。
...
**长度不是加分项。** 一份 50 字的正确回答，比一份 500 字但推荐了花生的回答好得多。
```

注意最后那句是**直接把偏差点名了**。这不是巧合——
**你知道你的 judge 会往哪偏，就直接在标准里把那条路堵上。**

### ② 必须引用原文当证据 ★ 这条被严重低估

```
**你必须在 evidence 里原样引用回答中的一小段作为你打分的依据。**
```

为什么这一条这么值钱：

> 不要求引用时，judge 是在**凭整体印象**打分。
> 而"印象"恰恰就是长度、结构、排版、语气这些东西起作用的地方。
>
> 要求引用之后，它必须回到答案里**找出一句具体的话**。
> **一旦要找证据，"看起来很用心"就不管用了** —— 你不能引用一段"感觉"。

实测的 evidence 里，judge 引的正是 B 里推荐宫保鸡丁那句。**它被迫看见了。**

> ⚠️ 但要诚实：本实验**没有把这两条拆开单独测**，所以我不能断言哪条贡献更大。
> **练习 1 就是让你去拆。** 别信我，去测。

## 五、`pairwise`：没测到位置偏差，但方法才是重点

```
  A vs B：正序赢家 A，反序赢家 A   ✓ 一致
  A vs D：正序赢家 A，反序赢家 A   ✓ 一致
  C vs B：正序赢家 C，反序赢家 C   ✓ 一致
  C vs D：正序赢家 C，反序赢家 C   ✓ 一致

  位置偏差：0/4 对在交换顺序后结论翻转
```

**这次没有翻转。** 位置偏差在这个模型、这批样本上**没有复现**
（本仓库第 8 次预期落空了）。

但这一节的价值不在结果，在**方法**：

> **这是本实验里唯一一个不需要标准答案的测量。**
>
> 逻辑：如果 A 真的比 B 好，那么不管谁先出现，赢家都该是 A。
> 赢家一变，说明 judge 被和内容无关的东西影响了——**这是自相矛盾，
> 不需要外部标准就能判定。**

意味着：

> **你今天就能拿这一招去测你自己的评测系统。**
> 不用标注数据、不用请人打标、不用标准答案。
> 把每一对**正反各跑一次**，数翻转率。
>
> **翻转率 > 0，你的排行榜就有一部分是噪声。**

同理，**自我一致性**（同一个判断重复 N 次看方差）也不需要标准答案。
上面 `score` 那个 2/3/3 就是这么测出来的。

> **两个不需要任何标注就能做的偏差检查，没有借口不做。**

## 六、我自己在这个实验里踩的坑（值得单独写）

第一次跑 `score` 的时候，B 的三次得分是 **`0/2/2`**。

`0` 不是模型给的分——是我的 `_clean_score()` 在 **JSON 没解析出来**时返回的哨兵值。

于是发生了这件事：

- 那个 0 被算进了平均分（(0+2+2)/3 = 1.3）
- B 被标成了「自我不一致」

**但 B 其实没有不一致 —— 是我的解析失败了。**

> **一个评测系统自己的故障，被记成了被测对象的缺陷。**

修法在 `_ask_with_retry()` 里：解析不出来就重问一次，而不是当成 0 分。

> 这个坑值得单独写出来，因为它在真实评测里**极其常见**：
>
> - API 超时 → 记成「模型答不出来」
> - JSON 解析失败 → 记成「模型不遵守格式」（有时确实是，有时是你的解析器太严）
> - 限流重试没做 → 记成「这批样本表现差」
>
> **判断方法：你的失败率，和被测对象的质量，是不是同涨同落？**
> 如果一个"更差"的模型恰好也更慢、更容易超时，那你可能在测网络，不是在测模型。
>
> **先给你的评测器写测试，再拿它去测别人。**

## 七、练习答案

### 练习 1 ⭐ 把 rubric 拆开测

本实验没拆，所以这里只能给**预期**和**怎么判断**：

| 变体 | 大致预期 | 关键看什么 |
|---|---|---|
| 有标准，无引用 | 准确率应该还不错 | **稳定性**会不会掉？（引用是"锚"） |
| 无标准，有引用 | 准确率可能掉 | 它引的是**哪一句**？没有标准时它不知道该找什么 |

**别信这张表，去跑。** 这正是实验 4-1 那个 2×2 的做法：**一次只动一个变量。**

如果你跑出来的结论和我的预期不一样，**你的结论是对的**——
本仓库到目前为止已经有 8 次预期落空了。

### 练习 2 ⭐⭐ 造一份「更长的正确答案」

把 C 再加长一倍，`score` 模式下它大概率仍是 4~5 分（5 分封顶了）。

**所以要把量程放开**：把提示词改成 1~10 分再测，才看得出这个偏差
到底是**有上限的**还是**接近线性的**。

> 这也是一个通用的评测技巧：**量程太窄会掩盖偏差。**
> 1~5 分的量表上，"很好"和"极好"挤在同一格里，
> 你根本看不出 judge 有没有继续加分。

### 练习 3 ⭐⭐ 让 judge 先说理由再打分

通常**会有区别，而且是免费的改进**。

原理是模型的自回归特性：**先生成的 token 会成为后生成 token 的上下文。**

```json
{"score": 4, "reason": "..."}     ← 先出分，理由是给分数【找补】
{"reason": "...", "score": 4}     ← 先说理由，分数是理由的【结论】
```

第一种里，模型是**先拍脑袋给个数**，再编一句话圆回来。
第二种里，它必须先把判断过程写出来，分数只是收尾。

> 这和「必须引用证据」是同一个思路：**强迫它在给结论之前先落地到具体内容上。**
>
> ⚠️ 但注意：这招在**带思维链的模型**上收益会小很多——
> 因为它本来就在内部先想了。**又一个"经验会随模型过期"的例子。**

### 练习 4 ⭐⭐⭐ 多个 judge 投票

**答案是：3 个不同的 judge 明显更有用。**

关键区别：

| 做法 | 能降低什么 | 降不了什么 |
|---|---|---|
| 同一个 judge 跑 3 次取中位数 | **随机误差**（那个 2/3/3 的抖动） | **系统偏差** |
| 3 个侧重点不同的 rubric 投票 | 随机误差 **+ 部分系统偏差** | 三个 judge**共有**的偏差 |

> **重复解决不了系统偏差。** 一个偏爱长答案的 judge，
> 跑一百次仍然偏爱长答案，只是你现在对这个错误答案更有信心了。
>
> 这是统计学里最基础的一条，但在 LLM 评测里被违反得特别频繁：
> **大家用 self-consistency 去"提高可靠性"，其实只降低了方差，没动偏移。**

而多个不同 judge 也有上限：如果它们都是同一个基座模型，
**它们的偏差是相关的**。真正的多样性要来自不同的模型、不同的 rubric、
以及——最贵但最可靠的——**人**。

### 练习 5 ⭐⭐⭐ 用你自己的数据测位置偏差

抄 `judge_pairwise()`，套到你自己的评测上，每一对正反各跑一次。

**这是本实验里唯一一个你今天就能用、且零标注成本的东西。**

拿到翻转率之后怎么用：

| 翻转率 | 说明 |
|---|---|
| 0% | 这批对比里位置偏差不显著（不代表没有，只代表没测到） |
| 5~15% | 常见水平。**建议每对都跑正反两次取一致结果**，成本翻倍但结论可信 |
| > 20% | 你的排行榜有很大一部分是掷硬币掷出来的 |

## 八、把这一章接回前面

这个实验其实是在**回头审计前面五章**。

本仓库每个实验都有判据，而它们的可靠性差得很远：

| 实验 | 判据 | 会误判吗 | 本实验的对应 |
|---|---|---|---|
| 3-1 记忆 | 关键词 | **会**（实测出现过） | ← 就是 `keyword` 模式 |
| 2-3 脱敏 | 正则 | 会（只认识规则表里的） | |
| 3-5 检索 | 集合包含 | 不会 | |
| 4-1 工具 | 比对唯一正确调用 | 不会 | |
| 5-1 改代码 | **真的跑测试** | 不会，且检查的是**行为** | ← 最硬 |

**排序的规律是什么？**

> **判据离"真实后果"越近，就越可靠。**
>
> 关键词判的是「文本长什么样」——离后果最远。
> 单元测试判的是「代码干了什么」——就是后果本身。
>
> LLM-as-judge 卡在中间：它比关键词懂语义，但它判的仍然是「文本」，
> 不是「后果」。**所以能用测试的地方就别用 judge，
> 能用 judge 的地方就别用关键词。**

而当你**只能**用 judge 的时候（开放式回答、写作、对话质量——
这些确实没有单元测试），那就：

1. 写清标准，把已知偏差**点名堵上**
2. **要求引用证据**
3. 测位置偏差和自我一致性（**零标注成本，没有借口不做**）
