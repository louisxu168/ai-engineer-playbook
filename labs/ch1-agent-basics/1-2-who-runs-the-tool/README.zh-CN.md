# 实验 1-2：工具 —— 谁来跑，以及它返回什么

[English](README.md) · **简体中文**

> **这个实验有两个独立的论点，别把它们混在一起看：**
>
> **论点 ①（第 0~1 步）：谁拥有那个 while 循环。**
> 现在的模型自带工具，你可以**一行循环都不写**就做出会联网搜索的 agent。
> 代价是**可观测性** —— 出问题时你连它卡在哪一步都不知道。
> 顺带你会看到：`search` 返回的是**线索**不是答案，
> 这是 agentic search 和朴素 RAG 的分界线。
>
> **论点 ②（第 2 步）：工具返回什么，比循环怎么写更重要。**
> 循环一行不改，只把工具削弱（不给搜索 / 只给标题 / 只给 1 条结果），
> agent 的能力就塌了。
>
> 两个论点用的是同一套代码，所以放在一个实验里；
> 但它们回答的是**两个不同的问题**，第 2 步开头会再提醒你一次。
>
> **怎么学**：同一个问题跑五遍 —— 前两遍比「谁拥有 harness」（论点 ①），
> 后三遍比「工具好不好用」（论点 ②）。
> **顺序很重要：一定先 hosted 再 diy**，反过来对比就没感觉了。
>
> **需要多久**：核心部分 15 分钟，全做完约 40 分钟。
>
> 建议先做完[实验 1-1](../1-1-context/README.zh-CN.md)，这里会直接用到那个循环。

## 第 0 步：让厂商替你干活（5 分钟）

### 🔧 做什么

```bash
cd labs/ch1-agent-basics/1-2-who-runs-the-tool
python3 agent.py hosted
```

它会问你想查什么。直接回车看例子，挑一个复制，比如：

```
迪拜最高的建筑和上海最高的建筑，哪个更高？高多少米？
```

**不用 `pip install`，不用 API key。** hosted 模式用的是 Claude Code 自带的联网搜索。

### 👀 你会看到

先是这句：

```
  我们只做了一件事：把问题原样发出去，并允许它使用自带的 WebSearch。
  没有循环、没有工具定义、没有上下文拼接 —— 那些都在厂商那边跑。
```

然后等一分钟左右，一个漂亮的答案 + 一堆来源链接。最后：

```
  厂商内部跑了 4 轮（这几乎是它唯一愿意告诉我们的事）
```

### 🤔 现在问自己四个问题

答案质量很高对吧。那么：

1. 它搜了**什么关键词**？
2. 它打开了**哪几个网页**？
3. 中间**读到过什么**？
4. 有没有**失败重试**过？

### 💡 学到什么

**四个你一个都答不上来。** 你拿到的只有最后那段文字。

这不是缺陷，是**交易**：你用可观测性换开发成本。问题在于很多人做这个选择时，
根本没意识到自己在交易。

## 第 1 步：换成你自己跑（8 分钟）

### 🤔 先猜

同一个问题，这次循环和搜索工具全由我们自己实现。猜一下：

- 会比 hosted 快还是慢？ ___
- 答案质量会更好还是更差？ ___
- 你能看到多少中间过程？ ___

### 🔧 做什么

```bash
python3 agent.py diy "（复制你上一步用的同一个问题）"
```

> ⚠️ **问题必须完全一样**，否则不构成对比。程序跑完会打印现成的命令。

### 👀 观察什么

慢很多。但每一次搜索、每一段摘要、每一次失败，全在你眼前。**重点看这三处**：

```
第 1 轮  [工具] search({'query': '迪拜最高建筑 哈利法塔 高度'})
              -> {"error": "没搜到结果"}                    ← ① 搜索失败了

第 2 轮  [思考] 中文关键词搜不到，改用英文名称搜索。
        [工具] search({'query': 'Burj Khalifa'})  -> 命中   ← ② 它自己纠正了

第 3 轮  [思考] Shanghai Tower 摘要给出 632 米，但 Burj Khalifa 摘要没给数字，
                需要读正文拿到精确高度。
        [工具] read({'title': 'Burj Khalifa'})              ← ③ search 只给线索
```

（你的输出不会和这里一模一样 —— 模型是随机的。但这三类现象通常都会出现。）

### 💡 学到什么

**① 和 ②** 是真实 agent 的容错长相：工具返回错误 → 错误进上下文 → 模型看见 →
换策略。这也是为什么代码里工具出错都 `return {"error": ...}` 而不是抛异常。

**③ 最重要**：两次搜索都命中了，但上海中心的摘要**恰好**带了 632 米，
哈利法塔的摘要**没有数字**，所以它必须再调 `read` 去读正文。

> **`search` 返回的是线索，不是答案。**
>
> 这正是「agentic search」和「朴素 RAG」的分界线。朴素 RAG 把 top-k 检索结果
> 一股脑塞进 prompt 就完事；agentic search 会判断"这条线索够不够"，不够就去读正文。

**而这三件事，hosted 模式一件都不会告诉你。**

## 第 2 步：把工具弄坏（10 分钟）

> ### ⚠️ 这里换论点了
>
> 第 0~1 步问的是「**谁**跑这个循环」—— 厂商，还是你。
> 从这里开始，循环**一直是你在跑**，问的是另一件事：
>
> **同一个循环，喂给它的工具好不好用，差别有多大？**
>
> 下面三个模式（`no_search` / `diy_titles_only` / `diy_top1`）和「谁拥有 harness」
> **完全无关**。它们都是 diy 模式，只是把工具依次削弱。

现在证明一件事：**工具返回什么，比循环怎么写更重要。**

### 🤔 先猜（表格填完再跑）

| 模式 | 改了什么 | 你猜：轮数变化 | 你猜：还答得对吗 |
|---|---|---|---|
| `diy_titles_only` | `search` 只返回标题，不返回摘要 | | |
| `diy_top1` | `search` 只返回 1 条，而不是 3 条 | | |
| `no_search` | 完全不给搜索工具 | | |

### 🔧 做什么

```bash
python3 agent.py diy_titles_only "（同一个问题）"
python3 agent.py diy_top1 "（同一个问题）"
python3 agent.py no_search "（同一个问题）"
```

### 💡 学到什么

打开 `agent.py` 看 `execute_tool()` —— 这三个模式**只改了 `search` 的返回内容**，
`run_diy()` 循环里**一行代码都没动**。

> 如果 `no_search` 居然答对了，别急着当 bug。想想：这个问题的答案是不是太有名了？
> 想不通再看 SOLUTION。

## 第 3 步：读代码，对比两个函数（5 分钟）

### 🔧 做什么

打开 `agent.py` 第 4 部分，把两个函数**并排看**：

- `run_hosted()`
- `run_diy()`

### 👀 观察什么

数一下各自多少行。然后注意一件事：**`run_hosted()` 里没有循环。**

因为循环根本不在我们这边跑。

再看 `llm.py` 里对应的两个函数，它们的差别只有一个参数：

```python
complete()          # --disallowedTools        → 循环归你
complete_hosted()   # --allowedTools WebSearch → 整件事归厂商
```

### 💡 学到什么

两件事：

1. **你省掉的代码，等于你放弃的控制权。**
2. `run_diy()` 和实验 1-1 的 `run()` **是同一个循环**。
   「会联网搜索的 agent」不需要任何新机制 —— 换的只是工具。

## 第 4 步：怎么选？（想清楚这个表）

| | hosted | DIY |
|---|---|---|
| 开发成本 | 几乎为零 | 要写循环、写工具、调 prompt |
| 答案质量 | 通常更好（真·全网搜索） | 取决于你的工具 |
| **可观测性** | **几乎为零** | **全部可见** |
| 出错时能 debug 吗 | 很难 | 能定位到具体哪一步 |
| 能换搜索源吗 | 不能 | 能（公司内网、私有库…） |
| 能控制成本吗 | 有限 | 能（限轮数、加缓存、降级） |
| 数据出不出去 | 出去 | 你说了算 |

**没有标准答案。** 真实项目常见组合：

- 通用问答、原型验证 → hosted，快
- 需要接私有数据、审计日志、控制成本 → DIY
- 很多产品是**混合**：主流程 DIY，某些子任务调厂商托管工具

**这个实验想让你建立的判断力**：当你选 hosted 时，你放弃的是可观测性。
出事那天，你手上只有最终那段文字。

## 附：概念速查

### 三个工具的分工

| 工具 | 返回什么 | 为什么需要它 |
|---|---|---|
| `search(query)` | 标题 + 摘要（**线索**） | 找到可能有答案的地方 |
| `read(title)` | 词条正文开头（**内容**） | 摘要里往往没有精确数字 |
| `calc(expression)` | 算术结果 | 模型自己算数字容易错 |

**只给 search 不给 read**，它就只能用摘要里碰巧有的东西凑答案。

### 三种做法的递进关系

| 做法 | 依赖关系靠什么保证 | 代价 |
|---|---|---|
| 串行（一轮一个工具） | 循环结构强制 | 往返多，慢 |
| **并行（本实验的做法）** | **模型自觉 + 参数必须是字面量** | 判断错就出错误结果 |
| 让模型写代码调工具 | 变量引用，语言级保证 | 需要沙箱 |

第三种是 Programmatic Tool Calling —— 模型直接写代码，依赖用变量表达：

```python
p = search_products("keyboard")
r = get_rate("USD", "CNY")
total = p["usd"] * 3 * r["rate"]      # 这才是真正的依赖
```

**我们停在中间那档 —— 这是真实 agent 的主流做法，不是简化。**

## 卡住了？

| 你看到的 | 怎么办 |
|---|---|
| `✗ hosted 模式没跑完` | 再跑一次。这个失败是不确定的，重试通常就好 |
