## 这一章想让你建立什么

**10-1** 用同一个任务、同一个模型量了四种协作方式，判据是机械的
（8 个写死的编号，集合运算）。结果不太舒服但很有用：
**单 agent 完胜**——8/8 全找到、零误报、一次调用。没有一种多 agent 赢了它，
其中两种**严格更差**。

原因就是那一课：单 agent **已经把任务顶满了**，所以召回率无处可涨，
剩下能变的只有成本和误报。**这两样都变差了。**

真正能带走的是每种模式的**特征性失败**。按数据切分假设了"问题是局部的"——
跨条目的发现会**结构性地**消失。按关注点切分会过度上报，而且实测显示
**过度上报全部集中在那个唯一说不清定义的类别上**。复核员只能删不能加，
所以它买的是精确率、赌的是召回率——而这次它删掉了一个真问题，
**它自己写下的理由却在论证这条应该保留**。

这一章还包含了本仓库最锋利的一堂评测课：**我的标准答案错了，而模型抓住了它。**
一段被我标成"安全"的代码其实真的可以被利用，两个 agent 各自独立报了它，
而我的程序把它记成了"误报"。
