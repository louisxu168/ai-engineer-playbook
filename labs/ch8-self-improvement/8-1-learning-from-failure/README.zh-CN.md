# 实验 8-1：从失败中学习 —— agent 能不能不在同一个地方栽两次

[English](README.md) · **简体中文**

> **你会学到什么**
>
> 1. **「学教训」和「记事实」不是一回事** —— 实验 3-1 那套做法在这里**会失效**
> 2. 实测反直觉的结果：**原样记录打败了提炼总结**，而原因很值得琢磨
> 3. 提炼教训时最容易犯的错：**把具体值一起抽象掉了**
> 4. 评估「自我进化」最容易搞错的一点：**分不清「没学会」和「没见过」**
>
> **怎么学**：判据是机械的——数每单失败了几次工具调用。
> **会不会学习，看的是曲线降不降，不是合计多少。**
>
> **需要多久**：25 分钟。

---

## 先搞清楚问题是什么

实验 3-1 教 agent 记**事实**（这个用户对花生过敏）。这个实验教它记**教训**：

```
事实：  「alice 对花生过敏」        → 只对 alice 有效
教训：  「amount_cents 要填分」     → 对所有工单都有效
```

**教训更值钱**，因为它能迁移到**新任务**上。这也正是所谓「自我进化」的最小形态。

### 环境：文档是残缺的

场景是一个退款 agent，连着处理 3 个工单。它拿到的工具文档只有一行：

```
issue_refund(order_id, amount_cents, reason_code)
    对一个工单发起退款。成功返回 {"ok": true}。
```

但**真正的校验规则有三条，一条都没写在文档里**：

| 规则 | 什么时候会撞上 |
|---|---|
| 1. `amount_cents` 单位是分 | 任何一单（不过参数名本身就在提示） |
| 2. `reason_code` 必须从枚举里选 | 任何一单 |
| 3. **超过 500 元需要 `approved_by`** | **只有 T-3** ← 记住这条 |

> **这正是真实世界的样子：文档永远落后于实现。**
> 一个不会从错误里学东西的 agent，会在**每一个新任务**上重新撞一遍同样的墙。

## 第 0 步：先看不学习是什么样（5 分钟）

```bash
cd labs/ch8-self-improvement/8-1-learning-from-failure
python3 agent.py no_memory
```

### 🤔 先猜

三个工单，失败次数会是什么形状？递减、持平、还是递增？

### 👀 观察什么

**盯住那条曲线，别看合计。**

```
  工单 T-1：失败 ? 次
  工单 T-2：失败 ? 次
  工单 T-3：失败 ? 次
```

### 💡 学到什么

**曲线不降。** 它在 T-2 上重新犯了 T-1 犯过的错——因为对它来说，
每一单都是第一单。

> 这就是**没有跨任务记忆**的 agent 的常态：
> **它不会变笨，但它也永远不会变聪明。**

## 第 1 步：把失败记录原样带走（5 分钟）

```bash
python3 agent.py raw_log
```

每单结束后，把失败的**原始记录**（调用了什么、报了什么错）整段带到下一单。

### 🤔 先猜

曲线会降吗？

### 💡 学到什么

**会降。** 而且这是最省事的做法——**零额外模型调用**，纯粹是字符串拼接。

代价你应该已经能猜到了（回想实验 3-1）：**它只会越滚越大**。
3 单还好，300 单呢？

## 第 2 步：让模型提炼教训（6 分钟）★ 本实验的核心

```bash
python3 agent.py lesson
```

每单结束后，让模型把失败**总结成可复用的规则**再带走。
提炼用的提示词（`sys_extract`）写得很讲究：

```
1. 写成**可直接照做的规则**，不要复述这次发生了什么
2. **不要写只对这一单成立的细节**（具体订单号、具体客户、具体金额）
3. 一条只说一件事
4. 只写从失败里真正学到的
```

### 🤔 先猜

这应该比 `raw_log` 更好吧？——毕竟实验 3-1 就是这么教的
（好的提取提示词 > 原样存全部）。

### 👀 观察什么

**三件事一起看：**

1. 曲线（和 `raw_log` 比）
2. 它**学到的教训原文**（屏幕上的 `💡 学到`）
3. **做成了几单**

### 💡 学到什么

**结果和实验 3-1 相反。** 去 SOLUTION 看具体数字。

在看答案之前，先读一遍它学到的教训，然后问自己一个问题：

> **这条教训里，有没有把「真正有用的那个信息」也一起抽象掉？**
>
> 提示：规则 2 是「`reason_code` 必须是 DEFECTIVE / WRONG_ITEM / CHANGED_MIND 之一」。
> 它学到的东西里，**有没有这三个词？**

## 第 3 步：全量对比，以及一个必须分清的区别（5 分钟）

```bash
python3 agent.py all
```

### ⚠️ 读这张表之前，先记住一件事

**T-3 触发的是一条前两单从来没出现过的规则**（大额需审批）。

所以：

```
T-1 → T-2 降下来了   =  学到了 ✓
T-3 又冒出来失败     =  正常 ✓  —— 那是【没见过】，不是【没学会】
```

> **「没学会」和「没见过」是两回事，而它们在指标上长得一模一样。**
>
> 这是评估「自我进化」时**最容易搞错**的地方：
> 你看到失败次数没降到 0，就以为学习机制不管用——
> 其实它可能只是遇到了新东西。
>
> **要判断学习有没有发生，你必须知道哪些失败是"重复的"、哪些是"新的"。**
> 这个实验之所以能说清楚，是因为**规则是我埋的，我知道哪条是新的**。
> 你在自己的系统里，得自己想办法做到这一点。

## 第 4 步：自己动手改（练习）

### 练习 1 ⭐⭐ 修好提炼提示词

如果 `lesson` 模式表现不如预期，问题很可能出在 `sys_extract` 的第 2 条：

```
2. **不要写只对这一单成立的细节**（具体订单号、具体客户、具体金额）
```

**这句话有歧义。** 试着改成：

```
2. 不要写只对这一单成立的细节（具体订单号、具体客户、具体金额）。
   但是：**接口的合法取值、阈值、单位、格式要求属于通用知识，必须原样写下来。**
```

**先猜**：曲线会变吗？

> 这道题真正想教的是：**「抽象」和「丢信息」只有一线之隔**，
> 而那条线在哪，得由你在提示词里划清楚。

### 练习 2 ⭐⭐ 加第 4 单，复现同一条规则

在 `ORDERS` 里再加一单**大额**的（比如 T-4，700 元）。

**先猜**：T-4 上还会因为 `approved_by` 失败吗？

> 这才是检验「学没学会规则 3」的正确方法：
> **让同一条规则出现第二次。** 只出现一次的规则，你无法区分
> 「学会了」和「运气好」。

### 练习 3 ⭐⭐ 把教训存成文件

现在记忆只活在一次运行里。改成写进 `lessons.json`，下次运行接着用。

**先猜**：跑第二遍时，第一单还会失败吗？

> 这就是「跨会话的经验积累」——实验 3-1 是跨会话记事实，
> 这里是跨会话记教训。**同一个机制，不同的内容。**

### 练习 4 ⭐⭐⭐ 让教训会「过期」

加一条规则：某条教训如果连续 N 单都没用上，就删掉。

**先想清楚**：怎么判断一条教训"用上了"？

> 提示：这比听起来难得多。**你没法直接观测"因为记得这条所以没犯错"。**
> 这正是所有「经验库」类系统的真实难点——
> **积累容易，淘汰难。** 而不淘汰的库最终会退化成 `raw_log`。

### 练习 5 ⭐⭐⭐ 混合：教训 + 原文

同时带走**提炼的教训**和**最近一次的原始错误信息**。

**先猜**：能不能既拿到 `raw_log` 的准确性，又拿到 `lesson` 的紧凑性？

> 做完对着成本那一列看：多花的调用值不值？

## 附：概念速查

### 记事实 vs 记教训

| | 实验 3-1（记事实） | 本实验（记教训） |
|---|---|---|
| 内容 | 「alice 对花生过敏」 | 「金额单位是分」 |
| 作用范围 | 只对那个对象有效 | 对**所有**同类任务有效 |
| 提炼时该做什么 | **概括**（一次性事件 → 长期偏好） | **保留具体值**（枚举、阈值、格式） |
| 提炼过度会怎样 | 丢掉细节，但还认得人 | **变成正确的废话** |

> **同一个「提炼」动作，在两个场景里的正确做法是相反的。**

### 一条工程原则

> **教训里最值钱的部分，往往正是那个"看起来很具体"的值。**
>
> 「要确认枚举的合法取值」——正确，但没用。
> 「枚举是 DEFECTIVE / WRONG_ITEM / CHANGED_MIND」——**这才是教训。**

## 卡住了？

| 你看到的 | 怎么办 |
|---|---|
| `✗ 没找到可用的后端` | 按屏幕上三个选项装任意一个 |
| agent 拒绝调用工具 | 应该已经修好了（提示词里说明了这是模拟环境）。如果还有，见 SOLUTION 第 5 节 |
| 曲线和文档不一样 | **正常**，模型是随机的。看的是**形状**：降不降、在哪一单降 |
| T-3 总是失败 | **那是设计好的** —— 它触发的是前两单没出现过的新规则 |
| 想看模型收到的原文 | 把 `SHOW_PROMPT` 改成 `True` |
| 忘了有哪些命令 | 敲 `python3 agent.py`（不带参数） |
