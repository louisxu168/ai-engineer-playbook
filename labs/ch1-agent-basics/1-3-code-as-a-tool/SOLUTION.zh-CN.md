# 实验 1-3 参考答案

[English](SOLUTION.md) · **简体中文**

> 自己跑过、预测错过之后再读。
> **不想跑命令也没关系** —— 下面每一节都贴了真实运行输出，看着就能懂。

实测环境 `LAB_BACKEND=claude`。问题：
**「世界最高的 5 座建筑，平均高度是多少米？最高的那座比平均值高出百分之多少？」**

---

## 一、先看结果对比表

| 模式 | 轮数 | 工具调用 | 写了几段代码 | 算出的数字 | 你能验算吗 |
|---|---|---|---|---|---|
| `deep` | 9 | 17 | 1 | 均值 668.16，高出 **24.19%** | ✅ 能，代码在眼前 |
| `no_code` | 6 | 11 | 0 | 均值 668.16，高出 **24.2%** | ❌ 只能自己重算 |
| `no_read` | 5 | 13 | 0 | **也算对了** —— 它绕过了限制，见第四节 | ❌ |
| `hosted` | 厂商内部若干轮 | 看不见 | 看不见 | 看不见过程 | ❌ |

真值（我用 Python 独立验算）：

```
均值 = (829.8+678.9+632+601+599.1)/5 = 668.16
高出 = (829.8-668.16)/668.16 = 24.19%
```

---

## 二、⚠️ 一个必须说破的意外：`no_code` 也算对了

**这是本实验最重要的发现，而且它推翻了这个实验最初的设计前提。**

我一开始的假设是：「模型是语言模型，心算多位小数会错，所以需要代码工具。」

**实测把这个假设证伪了。** 我单独做了个更狠的测试 —— 直接给模型 20 个三位小数，
要求纯心算：

```
问：下面 20 个数是世界最高 20 座建筑的高度（米）：
    829.8, 678.9, 632, 601, 599.1, 555.7, 541.3, 530, 530, 528.1,
    509.2, 492, 484.5, 476, 468, 461.2, 452.5, 450, 442, 438.6
    请只在脑子里算：中位数、总体标准差、高于均值的有几个。

模型心算 : 518.65, 93.94, 7
真实答案 : 518.65, 93.9437, 7
```

**全对。** 中位数、标准差、计数，一个没错。

所以「模型算不对」**不是**给它代码工具的理由。这个实验一开始的框架是错的，
我把它改了。

---

## 三、那真正的理由是什么？三条

### 理由 1：你验不了

对比两种模式给出的答案：

**`no_code` 的答案**（散文推导）：

```
  [答案] 世界最高5座建筑：1) 哈利法塔 829.8 m…5) 平安金融中心 599.1 m。
         总和 = 829.8+678.9+632+601+599.1 = 3340.8 m，
         平均高度 = 3340.8 / 5 = 668.16 m。
         最高的哈利法塔比平均值高出 829.8 − 668.16 = 161.64 m，
         即 161.64 / 668.16 ≈ 0.2419 ≈ 24.2%。
```

写得很清楚，算式也列了。但你想确认它对不对，**只能自己拿计算器再算一遍**。

**`deep` 的答案**（附代码）：

```
  [工具] run_python
  ┌─ 它写的代码 ─────────────────────────
  │ h = {'Burj Khalifa': 829.8, 'Merdeka 118': 678.9,
  │      'Shanghai Tower': 632.0, 'Makkah Royal Clock Tower': 601.0,
  │      'Ping An Finance Centre': 599.1}
  │ vals = list(h.values())
  │ avg = sum(vals)/len(vals)
  │ top = max(vals)
  │ print('average =', round(avg,2))
  │ print('pct above avg =', round((top-avg)/avg*100,2))
  └──────────────────────────────────────
        -> {'stdout': 'average = 668.16\npct above avg = 24.19'}
```

这段代码你可以**直接复制到自己的 Python 里跑**。这才叫可验证。

> 工程上的差别不在「谁算得对」，在**「谁的结论可以被第三方复现」**。

### 理由 2：改假设很贵

这一条是实测中**自己冒出来的**，我没有设计它。

哈利法塔的高度有两个口径：**829.8 米**（含天线的总高）和 **828 米**（屋顶高）。
用哪个，均值和百分比都会变。

**有代码的那次，模型主动把两种都算了：**

```
  ┌─ 它写的代码 ─────────────────────────
  │ ...（前略）
  │ print('pct above avg =', round(pct,2))
  │
  │ # 用总高度 829.8（含天线）做敏感性检验
  │ vals2 = [829.8, 678.9, 632.0, 601.0, 599.1]
  │ avg2 = sum(vals2)/5
  │ print('alt avg =', round(avg2,2), 'alt pct =', round((829.8-avg2)/avg2*100,2))
  └──────────────────────────────────────
        -> {'stdout': 'average = 667.8\npct above avg = 23.99\n
                       alt avg = 668.16 alt pct = 24.19'}
```

它一次性给出了 **23.99%** 和 **24.19%** 两个结果，并说明差异来自口径。

**为什么它愿意做这件事？因为有代码的时候，"换个数重算"成本几乎为零** ——
复制四行、改一个数组。没有代码的时候，这意味着整套心算重来一遍，
所以它（和你）都倾向于不做。

> **工具不只是让 agent 能做某件事，还改变了它愿意做什么。**
> 这是这个实验里最微妙也最值钱的一条。

### 理由 3：规模一大就崩

20 个数它能心算。**2 万行日志不能。**

这个实验受限于维基百科能提供的数据量，没法演示这一条 —— 但你可以自己验证：
把练习 5 做了（加载一个几千行的 CSV），`no_code` 模式会直接告诉你它做不到。

## 四、⚠️ 第二个意外：`no_read` 也没坏，它绕过去了

我预期的是「拿掉 read → 数据不全 → 分析没法做」。**实测又错了。**

第 2 轮它确实撞墙了：

```
  [思考] search 摘要没有具体高度数据，直接读正文…
  [工具 1/2] read({'title': 'List of tallest buildings'})
        -> {"error": "本模式没有 read 工具，只能用搜索摘要里的信息"}
  [工具 2/2] read({'title': 'Burj Khalifa'})
        -> {"error": "本模式没有 read 工具，只能用搜索摘要里的信息"}
```

但第 3 轮它**改变了策略** —— 开始构造「能把数字逼进摘要里」的搜索词：

```
  [思考] read 工具不可用，只能靠 search 摘要，但目前摘要里没有任何具体高度数字，
         先针对前几座已知高楼分别搜索，期望摘要中带出米数。
  [工具 1/5] search({'query': 'Burj Khalifa 828 metres tallest building Dubai'})
  [工具 2/5] search({'query': 'Merdeka 118 height metres Kuala Lumpur'})
  [工具 3/5] search({'query': 'Shanghai Tower height metres'})
  [工具 4/5] search({'query': 'Abraj Al-Bait Clock Tower height metres Mecca'})
  [工具 5/5] search({'query': 'Ping An Finance Centre height metres Shenzhen'})
```

注意它在查询词里塞了 `height metres` —— 这是在**诱导搜索引擎返回带数字的摘要**。

最后它拿到了全部 5 个数，而且给每一个都标了出处引文：

```
  [答案] 世界最高的 5 座建筑（数据取自维基百科搜索摘要）：
  1. 哈利法塔 828.0 m —「ranks Burj Khalifa in Dubai as the tallest at 828 m」
  2. Merdeka 118  678.9 m —「Merdeka 118 (678.9 metres or 2,227 feet)」
  3. 上海中心大厦 632.0 m —「the 632 m (2,073 ft) tall, 128-story Shanghai Tower」
  4. 麦加皇家钟塔 601.0 m —「stands at a height of 601 m…fourth-tallest building」
  5. 平安金融中心 599.1 m —「115-storey, 599.1-metre (1,966-foot) supertall」
```

**教训（比我原来想教的更重要）：**

> **Agent 会绕过你给它设的限制。**

你拿掉一个工具，它不会乖乖失败，而是用剩下的工具想办法达成同样的目的。
这有两面：

- **好的一面**：真实 agent 的鲁棒性比教科书上的失败模式强得多。
- **要小心的一面**：**消融实验很难做干净。** 你以为砍掉了「读正文的能力」，
  它却用「构造更精准的搜索词」补了回来 —— 你测的其实是另一个东西了。

这和实验 1-1 里 `no_history` 靠 `reasoning` 字段走私状态，是完全同一类现象。

## 五、`hosted` 模式：连验都没得验

它答得又快又好。但你**看不到它用了哪几个数、怎么算的**。

前面 `deep` 模式里那段代码 —— hosted 模式下也一定发生了类似的计算，
但你拿不到它。**理由 1 和理由 2 在 hosted 模式下全部失效。**

这和实验 1-2 的结论完全一致：**选 hosted，放弃的是可观测性。**

## 六、练习答案

**1. 换个需要更多数据点的问题** —— 你多半会发现三种模式**答案还是一样**。
这正是本实验最反直觉的地方：差别不在「对不对」，在「可不可复现」。
真想看它崩，得把数据量推到心算够不着的量级（见练习 5）。

**2. 把 `CODE_TIMEOUT` 改成 1 秒** —— 稍微复杂的代码会被杀掉，模型收到
「代码跑了超过 1 秒还没结束」，通常会改写成更简单的版本重试。
这演示了**工具的约束会反过来塑造模型的行为**。

**3. 让 `run_python` 返回假结果**（比如永远返回 `{"stdout": "42"}`）——
绝大多数情况它**照单全收**。和实验 1-1「让 `get_rate` 返回 999」、
实验 1-2「让 search 返回过时数据」是同一个结论：**模型默认信任工具返回值。**

**4. 数一下 `run_python` 有多少行安全防护** —— 只有一个 `timeout`。
这远远不算沙箱。真实项目必须放进容器里跑，见代码里那段 ⚠️ 注释。

**5. 加一个几千行的 CSV** —— `deep` 模式几行 pandas/csv 就搞定；
`no_code` 模式会直接告诉你它做不到。这是「规模」那条理由的实证。

## 七、一句话总结

| | 你拿到什么 | 能复现吗 |
|---|---|---|
| `no_code` | 一段写得很清楚的散文推导 | ❌ 只能自己重算 |
| `deep` | 一段可以复制去跑的代码 + 输出 | ✅ |
| `hosted` | 一个结论 | ❌ 连过程都没有 |

**给 agent 代码工具，不是因为它算不对，是因为你需要一个能被第三方复现的结论。**

顺带记住两个意外：

1. **有了代码，它会主动做敏感性检验。** 工具改变的不只是能力，还有意愿。
2. **Agent 会绕过你设的限制。** 这让消融实验很难做干净 ——
   你以为砍掉了 A，它用 B 补了回来。

这两条加起来还有个更大的启示：**这个 Playbook 里很多「教科书式的失败模式」，
在今天的模型上并不会稳定复现。** 与其背失败清单，不如养成
「先猜 → 实测 → 承认猜错」的习惯 —— 那才是这套实验真正想教的方法。
